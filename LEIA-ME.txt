Tabelaço — o dono do time entra pela página inicial
====================================================

ORDEM: rode a migration ANTES de subir o front. Sem ela, o login pela
página inicial avisa que o servidor ainda não foi liberado.

1) BANCO — Supabase → SQL Editor → cole e execute:

     supabase/migrations/0028_team_login_email.sql

   É idempotente: pode rodar de novo sem medo.

2) FRONT — copie por cima, mantendo os caminhos:

     src/index.css
     src/lib/email.ts                     (NOVO)
     src/lib/teamSession.ts               (NOVO)
     src/services/registration.ts
     src/components/Landing.tsx
     src/components/TeamRegistration.tsx
     src/components/TeamsPanel.tsx

   Depois: npm run build


COMO FICA
---------
A CRIAÇÃO da conta não muda: continua sendo pelo link que o organizador
envia (#/t/<time>?k=<token>). O que muda é que o login agora é um
E-MAIL VÁLIDO, e não mais um usuário inventado.

Depois de criada a conta, o gestor entra pela PÁGINA INICIAL do
Tabelaço — a mesma caixa "Entrar" do organizador — só com e-mail e
senha. O app reconhece que é gestor de time e abre o portal do time
direto, sem pedir o link.

Se o mesmo e-mail gerencia times em campeonatos diferentes, a página
mostra a lista para ele escolher qual abrir.

Cada time continua podendo ter 2 gestores; agora cada um com o próprio
e-mail e a própria senha.


O QUE NÃO MUDA
--------------
• Só o link do organizador cria conta de time. Ninguém entra em um time
  sem ter sido chamado.
• Contas antigas, com usuário que não é e-mail ("leoes.fc"), continuam
  entrando pelo link exatamente como antes. Nada é apagado nem migrado
  à força — apenas não é mais possível criar contas assim.
• Zerar a senha continua sendo do administrador, e a nova senha continua
  sendo criada PELO LINK. É de propósito: se desse para redefinir só com
  o e-mail, bastaria saber o endereço de um gestor com a senha zerada
  para entrar no time dele.
